The problem: every turn re-sends everything

A coding agent harness accumulates context. Every tool call adds output, every file read adds tokens, and on turn n you ship the entire history to the model again. Cost per turn grows linearly, so session cost grows roughly quadratically — while most of that context no longer matters.

What Jev is

Jev is a decision model, not a chat model. You send state (text or JSON) plus a map of typed questions, and you get typed answers back in one round trip. It never writes prose. Three primitives:

PrimitiveQuestion shapeAnswerUse when
noulyes/nonoul: 0…1a property may or may not hold (spam, injection, done, relevant)
choiceone of ≤255 named optionschoice + full probabilitiesone label or route must win
scoreordered levels (2…10)score + legend + probabilitiesdegree along a rubric (severity, quality, difficulty)

All questions in one request are evaluated in parallel against the same state, so adding questions is nearly free in latency. That is what makes speculative fan-out practical: ask everything you might need, then let code ignore the branches it does not take.

Why it changes harness economics

Price

$0.042 per million input tokens. Output tokens are free. A frontier LLM is roughly $3/Mtok input — about 70× more, before output tokens.

Published rate for Jev 1.13, per the official models page.

Speed

Non-autoregressive: one forward pass, no text decoding. Published median in a 3,080-utterance independent run: 175 ms vs 2,266 ms for a frontier LLM on the same task.

Fast enough to gate a new tool result before the next agent turn.

Shape

Answers are typed and carry probabilities, so control flow stays in code. You do not parse prose, and you do not give the model side effects.

Role

The LLM still writes, plans and reasons. Jev answers the small bounded questions around it: keep or drop, route or escalate, pass or block.

The architecture in one line

unstructured state  ->  Jev: bounded typed judgment  ->  ordinary code: thresholds, routing, side effects
What Jev is not. Typed output guarantees the interface, not the truth. Confidence describes the answer distribution, not correctness. Thresholds must be fitted on your own data. Treat everything here as a mechanism to measure, not a guarantee.

Cost lab: how Jev reduces context and spend in a harness

  

    A harness can use Jev four ways. Each one removes tokens from the context that
    the expensive model has to read, or removes the expensive call entirely. Set the
    assumptions below and compare the arithmetic.
  


  

    

      
1

      
Prune

      
Jev judges each new tool result: keep it verbatim, or drop it.
      Dropped tokens never enter the context window again.

      
noul — "Does this tool output still matter for the task?"

    

    

      
2

      
Route

      
Jev scores the turn's difficulty and sends easy turns to a cheap model,
      keeping the frontier model for hard ones.

      
choice — easy · medium · hard

    

    

      
3

      
Replace

      
The turn only needed a decision (which tool, which file, continue or stop).
      Jev answers it and no LLM turn happens at all.

      
choice — which action next

    

    

      
4

      
Verify

      
Cheap semantic checks on every prompt, tool call and response — injection,
      policy, tool errors, hallucination. Catches failures that otherwise burn a whole
      LLM turn and a human's time.

      
noul per failure mode

    Read this as a model, not a benchmark. The arithmetic below is exact;
    the keep rate, routing split and replace rate are assumptions
    you own. The honest procedure is: ship the lever in shadow mode, log how often Jev
    agrees with what you would have done, then set the rate from your own logs. Independent
    published measurements of the same idea: a 0.80-confidence gate that escalates the rest
    to a frontier model matched that model's accuracy at roughly a quarter of the cost
    (ayautomate);
    81.0% vs 84.4% accuracy, 175 ms vs 2,266 ms, $0.11 vs $2.42 per 1,000 items
    (OpenRouter).
  







  
When to use Jev — and when not to


  
Three tools are available for any step in a harness. Pick by what the step actually needs.


  

    
Reach forWhenExamples

    
      

        Deterministic code
        the rule is exact, countable, or already known
        arithmetic, schema validation, regex on a stable format, permission checks, retry policy, thresholds
      

      

        Jev
        the step is a bounded judgement over natural language, and you want it cheap, fast, and repeatable millions of times
        keep/drop a tool result, route to a model or queue, is this injected, is this done, which candidate is relevant
      

      

        Frontier LLM
        the step must produce something open-ended, or reason over many steps
        writing code, composing an answer, multi-hop planning, novel synthesis
      

    
  


  
The decision test

  
    
    
  1. Can code answer it? Use code. A model that is not called cannot be wrong or expensive.
    2. 
    
  2. Is the answer one of a closed set of names, a probability that a property holds, or a position on an ordered rubric? That is Jev.
    3. 
    
  3. Does the output have to be new prose, new code, or a long reasoning chain? That is the LLM.
    4. 
    
  4. Is it a closed-set question but your accuracy bar is very high? Jev plus a confidence gate that escalates — you pay frontier prices only on the uncertain tail.
    5. 
  


  
Harness patterns worth building

  


  
Anti-patterns

  

    
Using Jev for open-ended output
It cannot write your summary or your code. Pair it with the LLM instead of replacing it.

    
Asking two questions in one
One narrow judgement per question. Split independent dimensions; combine in code. Related dimensions that must be judged together belong in one question, with the relationship stated.

    
Treating confidence as permission
Confidence summarises the answer distribution. It is not a correctness guarantee. Gate, then measure.

    
Forgetting the cap
Choice takes at most 255 options; Score takes 2–10 levels. For bigger taxonomies, walk a tree with Choice at each level.

  







  
Reference


  

    
Endpoint

    
POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer <API_KEY>
Content-Type: application/json

    
Keys come from console.typesafe.ai/keys. Keep them server-side.

  


  

    

      
Request

      

        
          
statestring, object or array — what the questions are evaluated against. Required.

          
model"jev-latest", or a pinned id such as "jev-1.13.0".

          
questionsmap of id → question. Your ids come back unchanged and are not sent to the model.

        
      

    

    

      
Response

      

        
          
modelthe versioned id that answered — log this, it can change behind an alias.

          
answers[id]noul 0–1, or choice/score plus probabilities and confidence.

          
usageinput_tokens, output_tokens. Output is free.

        
      

    

  


  

    
Question types

    
// noul — probability that a statement holds
{ "type": "noul",
  "instructions": "Does this tool output still matter for the task?",
  "criteria": { "true": "still needed", "false": "safe to drop" } }

// choice — one of at most 255 named options
{ "type": "choice",
  "instructions": "Which model tier should handle this turn?",
  "criteria": { "easy": "mechanical edit", "hard": "multi-file reasoning" } }

// score — ordered levels, at least 2 and at most 10
{ "type": "score",
  "instructions": "How much does this turn depend on prior context?",
  "criteria": ["self-contained", "needs some context", "needs the whole history"] }

    

      instructions may be a string, object or array. Put the question in one
      field and the data it references in others, then point at the data with backticked
      names — the same way you point at a nested field of state.
      criteria for choice is the option list; for
      score it is the ordered level list.
    

  


  

    

      
Limits (Jev 1.13)

      

        
          
Price$42 per Btok = $0.042 / 1M input tokens; output free

          
Context64k per request; 32k for state plus the longest question

          
Rate250,000 tokens/s and 1,200 requests/min (adjusting dynamically)

          
Choice≤ 255 options

          
Score2–10 levels

          
Inputtext only — pre-convert image, audio and video to text

        
      

    

    

      
Errors

      

        
          
401missing or invalid key

          
403authentication error (what this endpoint returns for a missing bearer token)

          
422body failed validation; the response names the bad field

          
429rate limit — retry with exponential backoff

          
529overloaded — retry with exponential backoff

        
      

      
Honour Retry-After. The official SDKs retry with backoff by default.
